# 継続的な品質改善

## 日常の使い方

おかしい操作の直後、タイトルバーの虫アイコンまたはヘルプメニューの「今おかしかった：診断情報を保存」を選ぶ。ローカルにJSONを保存し、問題の説明と一緒に共有する。外部への自動送信は行わない。UIが停止して保存できない場合は、再起動後に保存する。

診断情報はアプリのデータディレクトリの `diagnostics` に保存する。通常は `~/Library/Application Support/neuraOS/Developer/diagnostics`。app / daemonそれぞれ約1 MiB×2世代でローテーションする。会話、ファイル内容、端末入出力、トークン、URL、パス、エラーメッセージは記録しない。操作ID、操作種別、時刻、ビルド、所要時間、数値エラーコードのみを記録する。端末入力・リサイズの成功は記録対象外。診断保存先は所有者のみ読み書き可能にする。

## 切り分け

- `action.blocked`: 同じ作業の処理が進行中。別の作業の操作やタブを閉じる操作は妨げない。
- `operation.start` → `received` → `executing` → `success/failure`: operationIdでアプリとDaemonを突き合わせる。receivedとexecutingの差がDaemonのキュー待ち。
- `operation.slow`: 10秒を超えた操作。タイムアウトしても再送しない。更新・削除・端末入力が実行済みの可能性があるため、状態を確認してから操作する。
- `ui.hang` / `ui.recovered`: メインキューが5秒以上応答しなかった。バックグラウンドで検知し、主スレッドに確認要求を積み上げない。
- `session.unclean`: 正常終了記録がない終了。強制終了、OS終了、クラッシュ等を含み、クラッシュとは断定しない。
- `crashes`: macOS DiagnosticReportsのneuraOS .ipsの直近最大10件から、日時・バージョン・incident ID・例外種別・シグナル・イメージUUIDとオフセットなど限定したメタデータだけを保存する。生のスタックやメモリは共有しない。詳細調査で生のレポートが必要な場合は別途確認する。

ビルド時にアプリの外側へ `neuraOS.app.dSYM` を生成し、CIでは90日間保持する。クラッシュのイメージUUIDと一致するビルドのシンボルを使ってコード位置を特定する。古いビルドを長くサポートする場合は保存期間を延ばす。

## 毎週のレビュー

保存した報告をまとめて集計する（重複した報告は除外する）。

```sh
node scripts/reliability/summary.mjs report1.json report2.json > weekly-summary.json
```

直近7日とその前7日をビルド別に比較する。観測したセッション数、正常終了／不明終了、UI停止回数、操作失敗率、長時間操作、失敗の多い操作を確認する。ローテーションで古い記録が消えるので全利用者の統計とは扱わない。終了結果が不明の操作を成功と見なさず、失敗率は開始・終了の両方が残る操作から求める。クラッシュのないセッション割合はOSレポートとセッションの対応を確定できるまで算出しない。

1. データ消失／クラッシュ、作業不能、遅さの順に、頻度も考慮して優先順位を決める。
2. Issueにビルド番号、操作ID、再現手順、期待する挙動、影響を残す。診断JSONを公開Issueに添付する前に内容を確認する。
3. 再現テストを先に用意し、修正前に失敗することを確認してから修正する。
4. 型チェック、Daemon・Swift・配布テストを通す。UIの修正は下記の実アプリ確認も行う。
5. 配布ビルド番号をIssueに残し、翌週の同じ指標が減ったか確認する。マージ、配布、実機での改善確認を分ける。

CIはPRごとに実行し、毎週の定期実行でも回帰を確認する。ローカル報告の収集・Issueの起票・改善判断は手動。CIだけで実利用のクラッシュ率を計測したとは扱わない。

## 実アプリの確認

配布用ビルドを一時領域で起動する自動スモークでは、アプリ自身のサイドバーボタン操作、バックグラウンド処理中のタブ選択・閉じる操作、診断保存を確認する。通常のDaemonや作業データに接続させない。実運用では以下も確認する。

- リモート更新中に別の作業へ移動し、タブを開閉し、端末を操作できる。
- 同じ作業への更新・削除の重複要求は抑止され、処理名と経過時間が出る。
- 接続断から復帰した際、入力を勝手に再送せず操作できる。
- スリープ復帰、長時間の端末出力、ブラウザとエディタを併用してUIが応答する。
- 診断保存と再起動後の回収ができる。強制終了は作業を保存したテスト環境のみで行う。
