# neuraOS

macOS向けのタスク駆動AI作業環境。目的、計画版、実行、承認、成果物、検証、記憶を一つのタスクで管理します。

**現在の版は開発版 0.1.0 です。完成版の受け入れ完了ではありません。** ローカルの縦断動作と耐障害性の試験を実装済みです。両モデルで相談・分担・成果物集約の実動作を確認済みです。Neon/R2本番接続、長期運用、配布・更新の受け入れは未完了です。固定fixtureの結果を実AIの成功率として扱いません。

## 起動

Node.js 24.13以上の24系、pnpm 11.9.0、macOSが必要です。生成コードの検証にはDockerを利用します。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

ブラウザ開発画面：<http://127.0.0.1:1420>。Runnerは127.0.0.1:4317で動作します。
初期画面は副社長チャットです。端末でログイン済みのCodexを既定で使い、Claude Codeへ切り替えられます。架空のタスクは入りません。

ネイティブアプリと常駐Runner：

```sh
pnpm service install
pnpm desktop:build
open apps/desktop/src-tauri/target/release/bundle/macos/neuraOS.app
```

常駐構成の保存先は `~/Library/Application Support/neuraOS`。開発用 `pnpm dev` の保存先 `.data` とは別です。`NEURA_DATA_DIR` で明示的に統一できます。LaunchAgentはログイン中に動き、ログアウト・スリープ・電源断中は実行しません。ウィンドウを閉じるとトレイへ移り、Runnerは継続します。

```sh
pnpm service status
pnpm service restart
pnpm service stop
```

## エージェント

- Codex CLI 0.163.0のApp Server（stdio、JSONメッセージ）。`NEURA_CODEX_PATH` で実行ファイルを指定できます。
- ローカルのClaude Code CLI 2.1.304の構造化出力。`NEURA_CLAUDE_PATH` で実行ファイルを指定できます。
- この個人用構成では、端末のCodexログインとClaude Codeログインを使用します。資格情報は親プロセスだけが読み、モデル子プロセス・UI・履歴には渡しません。未ログイン時は `codex login` / `claude auth login` で認証してください。任意のAPIキーを `app.neuraos` のKeychainに保存する方法もあります。期限切れのCLI認証は再ログインが必要です。
- 第三者への配布で定額契約を利用できるという保証は含みません。認証条件と配布条件は別途確認が必要です。
- モデル未指定時は各ランタイムの既定値を使い、実際のモデルとセッションIDを記録します。
- エージェントは制限されたmacOSプロセス内で、構造化した成果物を返します。推論通信は専用のローカルプロキシを経由し、実キーは親プロセスが付与します。
- ホストの任意シェルや外部サービスへの直接接続を許可しません。JavaScript成果物のテストは `docker run --network none --read-only` 内で行います。
- 現段階のエージェント連携は**構造化成果物の生成が中心**です。Git worktreeへの検査付きファイル変更とNode.jsの隔離テストを実装しています。任意言語のビルドとAIによるブラウザ自律操作は未対応です。

`pnpm doctor` はCLI、Docker、隔離内のCodex App Server初期化、利用可能な認証を確認します。推論は呼び出しません。

実推論を伴う検証は `NEURA_PROBE_PROVIDER=codex pnpm exec tsx scripts/probe-team.ts`（または `claude`）です。実利用データと別の `.tmp/team-probe` に、相談→部長の計画→社員2人→集約を作成します。費用・利用枠を消費します。

## クラウド

利用者の指示によりSupabaseは不採用です。

| 責任 | 実装 |
|---|---|
| 正本DB | 標準PostgreSQL。Neonへ接続可能 |
| 成果物 | S3互換ストレージ。Cloudflare R2向け |
| 認証 | GitHub OAuth device flow。Cloud APIはGitHubの数値ユーザーIDを許可リストで確認 |
| Cloud API | Fastify / Node.js。Dockerfileを同梱 |
| スケジューラ | Cloud API内の周期処理。PC停止中も期限を管理 |

DB・ストレージの管理資格情報はCloud API側だけに置きます。RunnerにR2キーやDB接続文字列は配布しません。

セットアップは [クラウド運用手順](docs/runbooks/cloud.md) と [.env.example](.env.example) を参照してください。クラウド未設定時は、画面に「ローカル保存」と表示します。

## 成果物の名前と保存

成果物名は `src/main.ts` のような相対パスを含められます。絶対パス、親ディレクトリへの移動、バックスラッシュ、制御文字は拒否します。名前は表示用の情報で、実体はRun内のUUIDで保存します。成果物の登録だけでは接続プロジェクトへファイルを書き込みません。単体ダウンロードには末尾のファイル名を使います。

生成結果をチェックポイントに保存し、登録途中で止まっても保存済みのID・内容を照合して未登録分だけ再開します。再開にモデルを呼び出す必要はありません。旧版の `invalid_artifact_name` で止まったCodex実行は、対応するセッション履歴を `pnpm exec tsx scripts/recover-artifact-output.ts <task-id>` で検証してチェックポイント化できます。その後にタスクを再開します。これは成果物保存の復旧であり、コード反映やテスト実行の成功を意味しません。

## チームの資料と予算

計画時はファイル一覧と短い概要、社員には部長が選んだ担当ファイルを渡します。担当指定がない既存計画では、目的・パスから関連資料を選びます。資料を省略した場合は明記します。集約時は社員の報告と検証記録を再利用し、リポジトリ全体や以前のモデルセッションを重ねて送信しません。元の成果物は省略せず保存します。

チームの既定上限15万トークンは維持し、計画に最大20%、最後の集約に25%（最大4万）を確保します。社員の配分は計画で実際に消費した分を差し引いて決めます。開始前にトークンと呼び出し回数を予約し、完了時に実測値で精算します。中断して使用量を確認できない場合は予約分を推定消費として保持します。

推論ゲートウェイでも入力サイズの見積もりと実測使用量から次の要求を止めます。入力トークン数の厳密な事前計算やプロバイダー側の出力上限ではないため、実行中の1要求が見積もりを超える可能性は残ります。ネイティブ社員端末はこの制御の対象外です。

予算不足で集約前に止まった場合、タスク詳細の「集約だけ再開」で完了済みの社員を再実行せず続行できます。過去の消費は残し、集約用の追加枠を確保します。チームの使用量・上限・実行中予約を画面で確認できます。

## 社長・副社長・部長・社員

- 副社長が全体の相談を受け、実在するプロジェクトへの依頼を提案します。「部長に依頼」で仕事を開始します。
- 左側のプロジェクトを開くと部長室です。AIと社員数（2〜4人）を選び、プロジェクトに限定した相談ができます。設定は新しい依頼に適用され、実行中の担当AIは変えません。
- 部長が担当を分け、社員が並行して成果物を作り、部長が集約します。現在の分担は独立した作業に限定し、任意の依存グラフではありません。
- Runnerは作業3枠と相談専用1枠を持ちます。社員の作業中も副社長へ相談できます。
- 部長の停止・一時停止は社員にも伝わります。最終成果物の受け入れは社長が行います。修正は部長へ相談し、新しい依頼として記録します。
- 全体相談には標準分類のプロジェクト概要だけを渡し、制限付きプロジェクトの内容はその部長室に限定します。

## 操作と制御

- 参照資料は選択したテキストファイル、または公開HTTPS URLから取り込みます。外部資料は権限や継続指示へ昇格させません。
- タスクの要件修正は計画の新版を作り、実行中の処理を中断します。
- 成果物の存在・文字列・JSON構文・利用者確認・隔離コンテナ内のNode.jsテストを完了条件として設定できます。
- GitHub Issue作成はリポジトリを限定した接続を登録し、具体的な本文を承認してからBrokerが送信します。メール送信や購入は実装していません。
- 結果不明の書き込みを再送しません。実行詳細で外部Issue番号を指定して、サービス側の本文と照合します。
- 記憶は根拠、適用範囲、版を持ち、編集・無効化・削除できます。モデルが提案した記憶を自動有効化しません。
- `local-only` は端末内下書きで保持できます。クラウド推論と同期へ送信しません。

## 開発ワークスペース

プロジェクト → ワークスペース → フォルダ設定からローカルフォルダを接続します。Monacoエディタ、ファイル一覧、xterm.jsの実ターミナルを使えます。macOS版は独立WebViewのブラウザを内蔵し、選択テキストまたはページ本文を「部長に相談」で送信前の下書きに取り込めます。

フォルダを接続すると、開発設定のチェックなしで部長・社員へファイル参照資料を渡します。Git未初期化のフォルダにも対応します。通常の調査・文書タスクは参照専用です。

開発はワークスペースの「エンジニアを起動」から担当名と依頼内容を入力します。プロジェクトのAI設定に従って、端末にインストール済みの **CodexまたはClaude Codeの対話CLIそのもの** を社員専用worktreeで起動します。JSONの変更案をneuraOSが適用する経路は使用しません。探索、編集、テスト、ツール、会話は各CLIが担当します。

- Codexは `workspace-write` / `on-request` / user承認、Claude Codeは `manual` 権限モードで起動します。必要な権限は各CLIの表示から直接回答します。承認画面の自動解析・自動回答はしません。
- 既存のCLIログイン・設定を使用します。ネイティブCLI端末は利用者がローカルでCLIを使うのと同じ信頼境界であり、neuraOSの推論プロキシやDocker隔離は介しません。worktreeはファイルの衝突回避でありセキュリティ隔離ではありません。
- 社員ごとの端末は切り替えても継続します。「終了」で停止します。Runner再起動後には自動再実行せず、同じworktreeでCLIの会話再開を選択できます。Codexはそのworktreeの最新会話、Claudeは社員に対応するsession IDを使います。
- プロジェクトの社員数が同時起動の上限です。ネイティブ端末のtoken・金額・呼び出し回数はneuraOSでは計測・制限していません。CLI終了をタスクの成功とみなさず、変更・テスト・マージは利用者が確認します。
- 専用worktreeの起動には、元のGitリポジトリの初回コミットと変更のコミットが必要です。Git未初期化でもファイル参照は利用できます。
- 調査・相談へ渡す資料はテキスト最大80ファイル・18万文字です。秘密設定パス、生成物、未追跡のignore対象、シンボリックリンク逸脱を除外します。未管理フォルダでは `.gitignore` も適用します。この上限はネイティブCLIの探索には適用しません。
- 社員端末からの変更は専用ブランチに残ります。現時点では部長の自動分担とネイティブ社員端末の自動起動・成果回収は接続していません。部長から渡された依頼を社員の起動時に入力できます。
- ファイルエディタは保存前のハッシュで競合を検知します。worktreeと社員の対応は端末内SQLiteに保持し、クラウドバックアップにはまだworktree実体を含みません。

チャットはVercel AI SDKのストリーム、Streamdown、コードのシンタックスハイライト、Mermaid、KaTeX、CJK、コピー・Markdown保存を利用します。CLIが部分応答を出さない場合は最終応答時の表示になります。

## 検証

```sh
pnpm check
NEURA_TEST_DOCKER=1 pnpm test
pnpm exec tsx scripts/test-postgres.ts
pnpm test:ui
pnpm eval
pnpm doctor
```

PostgreSQL試験は使い捨てコンテナを起動し、非SUPERUSER・非BYPASSRLSロールで実行します。UI試験は専用の `.tmp/ui-tests` を使用し、本番データを使いません。

50件の評価データは [cases.json](tests/evaluations/cases.json) にあります。`pnpm eval` は固定成果物に対する**検証器の試験**であり、AIタスク完了率90%を証明するものではありません。

## バックアップと復元

```sh
pnpm backup export /absolute/path/backup.json
NEURA_DATA_DIR=/empty/restore/path NEURA_DELETION_LEDGER=/path/latest.deletions.json pnpm backup restore /path/backup.json
```

バックアップは成果物本文を含みます。暗号化された外部保存先にコピーしてください。復元時は最新の削除台帳を先に適用し、端末を失効させ、実行を照合待ちにします。元データの上書きは拒否します。クラウド構成は `NEURA_DATABASE_PATH` で対象のキャッシュDBを指定できますが、未同期状態を含むためクラウドDBのバックアップの代わりにはなりません。

復旧目標15分/4時間は未実測です。[復旧手順](docs/runbooks/recovery.md) と [受け入れ状況](docs/acceptance.md) に証拠の境界を記録しています。

## 構成

DesktopのUI部品はRadix Themesを使用します。サイドバーはプロジェクトとタスクを直接選ぶ一覧です。

`apps/desktop`、`apps/runner`、`apps/cloud-api` と、`packages` 内の契約・ドメイン・権限・実行・記憶・同期・アダプターを分離しています。UIのファイル操作は型付きAPIを使います。利用者用ターミナルだけが明示的なPTY入力を受け、エージェントへは公開しません。

設計基準は [仕様の実装基準](docs/architecture/specification-v1.md)、設計上の選択は [ADR-001](docs/decisions/001-initial-architecture.md) を参照してください。
