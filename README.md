# neuraOS

macOS向けの、自分用のAI開発ワークスペース。SwiftUIのネイティブUIと、独立したローカルDaemonで構成します。ターミナル表示には[SwiftTerm](https://github.com/migueldeicaza/SwiftTerm/tree/v1.20.0)のAppKitビューを使用し、PTYはDaemon側に置きます。

**0.2.0 開発版。** リポジトリ、worktree、対話CLI、ファイル、差分、プレビューを一つの画面で扱います。

## 起動

Node.js 24.13以降の24系、pnpm 11.9、XcodeのSwiftツールチェーン・Metal Toolchain、Gitが必要です。UIの対象はmacOS 14以降（実機確認環境はmacOS 26）。Codex／Claude Codeは各公式CLIをインストール・ログインして使います。

```sh
pnpm install --frozen-lockfile
# Metal Toolchainが未導入の場合のみ
xcodebuild -downloadComponent MetalToolchain
pnpm dev
```

`pnpm dev`はDaemonが未登録ならユーザーのLaunchAgentとして登録し、SwiftUIアプリをビルドして開きます。既に動いているDaemonは再起動しません。

生成先：`apps/macos/dist/neuraOS.app`

単独操作：

```sh
pnpm build
pnpm service status
pnpm service install
pnpm service stop
pnpm service restart
```

`install`と`restart`は既存DaemonのPTYを終了します。作業中は実行しないでください。アプリのウィンドウを閉じる／アプリを終了するだけならPTYは継続します。Daemon自身の再起動やログアウト・PC停止後は履歴を復元し、中断として表示します。生きていたプロセスを復元したとは表示しません。

ローカル開発ビルドのDaemonはこのチェックアウトとNode環境を参照します。mainへのマージ後はCIがNode／Daemon同梱の配布版をビルドし、GitHub Releasesへ公開します。neuraOSメニューの「アップデートを確認…」から更新できます。更新時はDaemonも再起動するため、作業を保存してください。現在は個人利用向けad-hoc署名で、公証は未導入です。初回導入・PR・検証・復旧手順は[開発・配布フロー](docs/development-release.md)を参照してください。

## 最初の作業

1. `⌘O`で作業するフォルダを開く。Gitリポジトリでなくても利用できます。
2. Gitリポジトリの場合は`⌘N`でプロジェクトを選び（既定はoriginのデフォルトブランチを毎回fetchした最新コミット）、専用ブランチとworktreeを作成。名前の入力は不要です。Codex・Claude Codeの会話名が付くと、左サイドバーのworktree表示名に自動反映されます（通常3秒程度）。会話名がない間は仮名を表示し、ブランチ名とフォルダのパスは変更しません。
3. タブバーの「＋」からCodex／Claude Code／Terminal／Browserを追加し、対話CLIをfull accessで起動。ログイン、会話再開はCLI自身の画面で行います。
4. タブを切り替えて作業。右サイドバーのエクスプローラー／Gitからファイルや差分を中央に開く。
5. アプリを終了してもDaemonは継続。再度開くと同じPTYへ接続し、出力を復元。

worktreeやタブを切り替えても、一度表示したターミナルの画面・スクロール位置・出力の読み取り位置を保持します。非表示中も低頻度で出力を取り込み、戻った際に先頭から再生し直しません。アプリを終了した場合は、従来どおり保存ログから復元します。

作業が終わったworktreeは、左サイドバーで右クリック →「worktreeを削除」から削除できます。対象のターミナル・エージェントは自動で終了し、作業フォルダとターミナル履歴を削除します。ブランチは残ります。未コミット・未追跡・Gitの無視対象ファイル（`.env`やローカルDBなど）がある場合だけ、破棄の確認が表示されます。キャンセルするとファイルと実行中のターミナルは維持されます。未保存の編集は先に保存または破棄してください。「メイン」と通常のフォルダは削除対象になりません。

Workspaceはプロジェクトを用途別にまとめるサイドバーのグループです。左下の`＋`または`⇧⌘N`で作成し、左サイドバー上のトラックパッドの左右スワイプ、下部のドット／矢印、`⌥⌘←`・`⌥⌘→`で切り替えます。既存プロジェクトは最初のWorkspaceに入り、プロジェクト名を右クリック →「Workspaceへ移動」で移せます。追加したフォルダは現在のWorkspaceに入ります。グループと選択中の作業はこのMacに保存され、切り替えても開いているターミナルや編集内容は保持します。

上部の左右サイドバーボタンで表示を切り替えられます。左は`⌃⌘S`、右は`⌘⌥\`でも開閉でき、状態は再起動後も保持します。両側を閉じると中央の作業領域が横幅いっぱいに広がります。ブランチとパスは下部のステータス行で確認できます。

会話名の定期取得は稼働中のCLIがあるworktreeだけで行います。CLI終了時は最後に一度取得し、その後は保存済みの表示名を使います。

通常のフォルダでは、そのフォルダでCLI、ターミナル、ファイル編集、ブラウザを使えます。Gitの初期化は行いません。worktree作成と差分表示はGitリポジトリのみで利用できます。後からそのフォルダでGitを初期化した場合も、定期的な状態更新で自動検出し、開いているタブや端末を保ったままGit機能を有効にします。worktreeの作成には最初のコミットが必要です。

「メイン」は元のフォルダ／リポジトリです。「リモートの最新に更新」でoriginのデフォルトブランチへ切り替え、最新コミットまでfast-forwardします。未保存・未コミットの変更、未追跡ファイル、実行中の端末、デフォルトブランチの未反映コミット、更新先と重なる無視対象ファイルがある場合は停止します。元の作業ブランチと既存worktreeは保持します。新規作成・更新ともリモート取得に失敗した場合は停止し、古い参照へフォールバックしません。リモートのないリポジトリでは、新規作成の「作成元を指定」でHEADなどを指定できます。専用作業はworktree上で行います。worktreeはファイル変更を分離するもので、セキュリティ境界ではありません。

- 同じworktreeでCodex、Claude Code、Terminal、Browserを複数の独立したタブとして追加できます。タブ数の固定上限は設けていません（利用可能な数はMacのリソースに依存します）。タブ構成・選択中のタブ・ブラウザごとのURLは再起動後も復元します。実行中の端末タブを閉じる際は停止を確認します。アプリを終了するだけならPTYは継続します。
- 複数端末の起動には対応済みDaemon（`terminal.multiple`機能）が必要です。旧Daemonでは既存PTYへの再接続は継続できますが、新規起動時は更新案内を表示します。保存済みのワークスペース単位のブラウザURLは、最初のブラウザタブに一度だけ引き継ぎます。
- Finderまたは右側のエクスプローラーから、Codex／Claude Code／Terminalの入力欄へファイルをドラッグ＆ドロップできます。複数ファイルやFinderでコピーしたファイルの`⌘V`にも対応します。引用符付きの絶対パスを入力し、送信は行いません。ファイルの読み取り・画像としての扱いは各CLIに従います。
- 新規起動・会話再開ともに、Codexは`--sandbox danger-full-access --ask-for-approval never`、Claude Codeは`--permission-mode bypassPermissions`を指定します。ファイル操作やコマンド実行の都度の権限承認なしで動作します。CLIや組織の管理ポリシーによる制限は引き続き適用されます。
- 起動済みの端末へ再接続しても権限は変わりません。起動設定の変更は、更新済みDaemonから新しくCLIを起動したときに適用されます。
- エージェントの起動ではCLIが通常のユーザー環境で自身の設定と認証を利用します。利用枠の表示では、CodexはApp Serverの読み取りAPI、Claudeは既存のKeychain（または標準の認証ファイル）のアクセストークンをメモリ内で利用します。トークンはneuraOSのDB・ログ・UIには保存・送信しません。
- ファイル編集は1MB以下のUTF-8テキスト。保存時のハッシュ照合で外部更新を検知します。未保存の編集はUI端末へ自動退避し、通常の終了・再起動後に復元します。強制終了時は直近約0.5秒分が失われる可能性があります。
- Git操作のうちworktree作成・状態取得・差分表示をUIから利用できます。GitHubへのpush・PR作成・PRマージは右サイドバーの「GitHub」から利用できます。commit、ローカルのmergeはターミナルで行います。
- ブラウザは独立したWKWebView。端末操作用のブリッジやDaemonの資格情報を持ちません。現時点ではUI端末からURLへ接続します。

左サイドバー下部にはCodex／Claudeのアカウント共通の利用枠使用率を小さく表示します。約1分ごとに更新し、ホバーでリセット日時を確認できます。返された枠だけを表示し、取得失敗・未ログイン・情報なしは0%と区別します。2分半以上更新できない値は「更新待ち」に切り替えます。Claudeの取得先はCLIの`/usage`と同じ非公開APIのため、仕様変更時は取得できない場合があります。対応Daemon（`provider.usage`機能）が必要で、旧Daemonには「更新が必要」を表示します。

## GitHub 連携

GitHub CLI（`gh`）をインストールし、ターミナルで一度ログインします。DaemonはCLI自身の認証を利用し、トークンをコピーして保存しません。

```sh
brew install gh
gh auth login --hostname github.com
gh auth setup-git
```

右サイドバーの「エクスプローラー」「Git」に並ぶ「GitHub」からPR・レビュー・CIを確認できます。中央の作業タブを切り替える必要はありません。`origin`と現在のブランチからPRを取得し、対応するOpen PRを優先し、なければ直近のClosed/Merged PRを表示します。表示中は30秒ごとに更新し、手動更新もできます。

アプリはDaemonの応答に含まれる `features: ["github"]` を確認してからGitHub機能を有効にします。`pnpm dev`で旧Daemonを起動したままアプリだけ更新した場合、右サイドバーのGitHubには更新案内を表示します。他の機能と既存PTYは継続して利用できます。作業を保存してDaemonを更新・再起動すると、アプリ側で対応を再検出します。

- **Push**：表示されたコミットとブランチを確認して送信。未コミットのファイルは含めません。force push・ブランチ削除は行いません。
- **PR作成**：タイトル、説明、マージ先、Draftを指定。既定はDraftで、作成前のPushも選択できます。
- **コメント確認**：通常のコメント、レビュー、コード行へのコメントを全ページ取得。PR本文とコメントはMarkdownで表示し、見出し・リスト・チェックリスト・引用・表・コードブロックに対応します。長いコードと表は横スクロールでき、コードはコピーボタンでコピーできます。CI、レビュー判定、未解決スレッド数とGitHubへのリンクも表示します。
- **マージ**：リポジトリで許可された方式を選択し、PR・マージ先・コミットを確認。Daemonが最新状態を再取得し、Open、非Draft、`CLEAN`、未解決スレッドなし、ローカルとPRのコミット一致を確認したうえで、GitHubへ期待するhead SHAを指定します。GitHubの保護ルールはそのまま適用されます。

初期対応はgithub.comの`origin`内で完結するPRです（HTTPS / SSH）。forkから別リポジトリへのPRとGitHub Enterpriseは対象外です。コメントの投稿・返信、スレッド解決、Draft解除は「GitHubで開く」から行います。マージキューや自動マージの設定もGitHub側で行ってください。

GitHubに接続できない場合は「PRなし」と扱わずエラーを表示し、古い表示からの操作を無効にします。操作の応答が不明な場合は状態を更新し、GitHub上で結果を確認してください。GitHubの通信中もターミナル入力とファイル保存は独立して利用できます。

## ショートカットキー（macOS）

メニューバーの「タブ」「表示」「サイドバー」からキー割り当てを確認できます。タブ操作は選択中の作業だけに適用されます。

| 操作 | キー |
| --- | --- |
| フォルダを開く | ⌘O |
| 新しい作業 / 新しいWorkspace | ⌘N / ⇧⌘N |
| 新しいTerminal | ⌘T |
| 新しいCodex / Claude Code | ⇧⌘T / ⌥⌘T |
| 新しいBrowser | ⇧⌘B |
| 現在のタブを閉じる | ⇧⌘W |
| 前 / 次のタブ（端で循環） | ⇧⌘[ / ⇧⌘] |
| タブ1〜8 / 最後のタブ | ⌘1〜8 / ⌘9 |
| 前 / 次のWorkspace | ⌥⌘← / ⌥⌘→ |
| 左 / 右サイドバーを開閉 | ⌃⌘S / ⌥⌘\ |
| エクスプローラーを表示 | ⇧⌘E |
| Git / GitHubを表示 | ⇧⌘G / ⌥⌘G |
| 編集中のファイルを保存 | ⌘S |

実行中のターミナルタブを閉じる場合は、プロセス停止の確認が表示されます。⌘Wは通常のウィンドウ操作に残しています。存在しない番号のタブは選択されません。Git関連の表示キーはGitを使用する作業で有効です。

## 構成

```text
apps/macos/           SwiftUI / AppKit / WebKitクライアント
apps/daemon/          Node.js / TypeScript / node-pty / SQLite
scripts/native/       ビルドとLaunchAgent管理
tests/native/         Daemonの統合・復旧試験
```

UIはGit・プロセス・プロジェクトファイルを直接操作しません。認証付きの`/v1` HTTP APIからDaemonへ要求します。端末出力と状態イベントには順序を持たせ、再接続時に再取得できます。通信契約は`apps/daemon/src/contracts.ts`、Swift側のモデルは`apps/macos/Sources/NeuraOS/Models.swift`です。

現在は`127.0.0.1:4318`限定で待ち受けます。UIとDaemonの接続に使うローカルトークンは権限0600のファイル、データディレクトリは0700です。ブラウザOrigin付き要求は拒否します。

保存先：`~/Library/Application Support/neuraOS/Developer/`

- `developer.sqlite`：プロジェクト、worktree、端末、イベント、出力、操作ID。
- `worktrees/`：Daemonが作成するGit作業領域。
- `daemon-token`：同一ユーザーのネイティブUI向け接続資格情報。
- `daemon.log` / `daemon-error.log`：サービスログ。

端末の出力はローカルに保存されます。現在は自動保持期限・ローテーションなしです。通常のユーザー権限のCLIを起動する開発ツールであり、未信頼コードを隔離するサービスではありません。

## 将来の別PC・スマホ操作

UI依存のXPCオブジェクトやローカルファイルURLを通信契約に使わず、Daemon所有のID、バージョン付きAPI、操作ID、イベント／端末出力カーソルを使用します。ターミナルの入力者には15秒の占有期間を設け、別のクライアントとの同時入力を拒否します。

遠隔接続はまだ有効化していません。次段階で端末ペアリング・失効、TLSとVPNまたは中継、入力権の明示移譲、開発サーバーのポート転送を追加します。クラウドDBはローカル利用の前提にしません。Windows／Androidには別のUIが必要ですが、DaemonのAPIは共有できます。

## 検証

```sh
pnpm typecheck
pnpm test
pnpm build
```

自動試験は独立した一時GitリポジトリとSQLiteで、認証、Origin拒否、重複操作、並行worktree、ファイルの競合・境界検査、PTYの入力・履歴、再接続、Daemon再起動時の中断表示を検証します。実際のモデルによる開発完了とは別の試験です。

### サイドバーのエージェント状態とCI

worktree行の右端には、エージェントの作業中をローダー、回答・承認待ちをオレンジの吹き出し、次の指示待ちを緑の点で表示します。複数のCodex/Claude Codeがある場合は回答待ちを優先し、ホバーすると各セッションの状態が見られます。状態を取得できない場合は「?」、終了したセッションのみなら停止アイコンになります。シェルの起動だけでは作業中になりません。

macOS通知はCodex／Claude Codeの「回答・承認待ち」と「応答完了」に対応します。初回の通知許可を有効にし、メニューバーの「通知」で種類別にオン／オフを切り替えられます。通知をクリックすると該当のWorkspaceとターミナルを開きます。本文は作業名のみで、会話内容は含めません。通知イベントは順序付きで永続保存し、ポーリング間に続いた回答待ち・完了もそれぞれ取得します。取得途中の切断後は続きから再開します。アプリ起動時の過去イベントや同じイベントを繰り返し通知せず、中断・エラー・セッション終了も完了扱いにしません。neuraOSアプリが起動中（ウィンドウを閉じた状態を含む）で、対応Daemon（`terminal.notifications`）と下記の状態連携が必要です。通常の文章での質問は応答完了として通知します。macOS側で通知が無効の場合は「通知 → macOSの通知設定を開く…」から許可してください。

状態連携は更新後にneuraOSから新しく起動・再開したCLIで有効になります。既に実行中のセッションには後からフックを挿入しません。Codexがフックの信頼確認を表示した場合は、そのセッションの `/hooks` でneuraOSの `agent-activity-hook.mjs` を確認してください。信頼確認や管理者によるフック無効化は迂回しません。Claude Codeは2.1.306以降、Codexはフック信頼確認と `--no-daemon` に対応したCLIを対象とします。対応していないCLI、無効なフック、イベントを通知しない特殊なツール経路は正確な状態を取得できない場合があります。通常の文章で尋ねてターンを終了した場合は「次の指示待ち」で、構造化された質問ツールによる回答待ちとは区別します。

フックはその起動にだけ追加し、ユーザーやリポジトリの設定ファイルを書き換えません。通知するのは状態判定に必要なイベント識別情報だけで、プロンプト・回答・ツール引数は保存しません。Codexはターミナルごとの環境を保持するため `--no-daemon` で起動します。

CIはエージェント表示の左隣に、実行中・成功・失敗・キャンセルのアイコンで表示します。対象はworktreeの現在のHEADで、表示中の行だけ60秒ごとに確認します。同じリポジトリ・コミットへの取得は共有し、GitHubへの同時問い合わせを4件に制限します。CI未設定・未pushのコミットではアイコンを省略し、認証・通信エラーは成功と区別します。チェック名はホバーで確認できます。既存の `gh auth login` を使用します。

仕様参照: [Codex hooks](https://learn.chatgpt.com/docs/hooks)、[Claude Code hooks](https://code.claude.com/docs/en/hooks)、[GitHub CLI API](https://cli.github.com/manual/gh_api)。

## 不具合の報告と継続改善

タイトルバーの虫アイコン、またはヘルプの「今おかしかった：診断情報を保存」からローカルの診断JSONを保存できます。操作履歴、無反応の検知、クラッシュ情報、週次集計と改善手順は [docs/reliability.md](docs/reliability.md) を参照してください。
